# Лабораторная работа № 1. Telegram-бот с языковой моделью

Источник: `docs/labs-guide.md` (раздел Lab 1). Максимум: **25 баллов**. Тег сдачи: `lab1`.

## Цель

Интегрировать Telegram-бота с LLM, реализовать управляемый контекст диалога и проверить влияние промпта и параметров генерации на ответы.

## Постановка

На базе стартового проекта — бот «AI-ассистент студента»:

- текстовые сообщения в личных чатах;
- вызов OpenAI-совместимой LLM;
- контекст на пользователя;
- ответ с учётом режима и `temperature`.

Режимы:

| Команда | Назначение |
|---|---|
| `/study` | объяснение учебных вопросов по программированию (режим по умолчанию) |
| `/translate` | перевод на язык, указанный пользователем |
| *(своя)* | отдельная задача, не только смена названия роли |

У каждого режима — своя системная инструкция; хотя бы один режим с few-shot. Структуру промптов разобрать в отчёте (R.C.T.F.: Role, Context, Task, Format).

## Функциональные требования

### Сообщения
- Только текст из личных чатов.
- `/start` — краткое описание возможностей и команд.
- Обычный текст → активный режим.
- Показать состояние обработки при долгой генерации.
- Не слать пустой ответ; echo не использовать как основной обработчик.

### Смена режима
- Сохранить режим в PostgreSQL.
- Очистить историю предыдущего режима.
- Подтвердить переключение; команду в LLM не отправлять.

### История
- Сообщения пользователя и успешные ответы ассистента в PostgreSQL.
- Разделение по chat/user id; роли и порядок.
- Лимиты через конфиг: по числу сообщений **и** оценочному объёму.
- При ошибке LLM ответ ассистента не сохранять.
- Контекст восстанавливается после рестарта.
- Системная инструкция и текущий запрос всегда сохраняются; история связная.

### `/settings`
- Показать режим, модель, `temperature`.
- Выбор: `0.0` / `0.3` / `0.7` / `1.0`; сохранить в БД; применить со следующего запроса.
- Настройки изолированы по пользователям; некорректное значение отклонять до API.

### `/reset`
- Удалить только историю текущего пользователя; режим и temperature сохранить.

### Ошибки и длинные ответы
Обязательно обработать: таймаут, недоступность/ошибка сервиса, пустой ответ, ответ > 4096 символов.
Пользователю — короткое русское сообщение без traceback/секретов/системного промпта.
Длинный ответ резать на части ≤ 4096 с сохранением порядка (`parse_mode` не обязателен).

## Нефункциональные требования

- API URL, ключ, имя модели — из env; примеры без секретов в `.env.example`; при отсутствии обязательного — понятная ошибка и выход.
- Разделить: handlers, LLM-клиент, промпты режимов, история/настройки, config.
- Логи: начало/результат внешнего вызова, модель, длительность, безопасный request id; без ключей, токенов, промптов и полного диалога.
- Тесты без реального Telegram и LLM API (моки).

### Обязательные тесты
1. Сообщение уходит в модель с инструкцией активного режима.
2. Истории двух пользователей не смешиваются.
3. Сокращение истории при лимите без потери текущего запроса и порядка.
4. Смена режима чистит историю и сохраняет настройку.
5. `/reset` чистит только историю вызывающего.
6. `/settings` принимает валидное и отклоняет некорректное.
7. Ошибка LLM → безопасное сообщение пользователю.
8. Ответ > 4096 разбивается без потери текста.

## Эксперимент
- Один запрос (без нужды в актуальном интернете); зафиксировать промпт, модель, константы, дату.
- Для каждого `temperature` ∈ {0.0, 0.3, 0.7, 1.0} — по 3 запуска (всего 12); перед каждым `/reset`.
- Таблица: номер, temperature, длина, формат да/нет, наблюдения, токены.
- Анализ вариативности; дополнительно — улучшение слабой инструкции (R.C.T.F. / few-shot).
