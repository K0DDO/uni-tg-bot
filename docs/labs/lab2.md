# Лабораторная работа № 2. Telegram-агент с MCP-инструментами

Источник: `docs/labs-guide.md` (раздел Lab 2), набор маршрутизации: `docs/evaluation/lab2-routing.json`.  
Максимум: **25 баллов**. Тег сдачи: `lab2`. Продолжение Lab 1 (отдельный демо-бот недопустим).

## Цель

Расширить бота до AI-агента: модель выбирает действие, приложение проверяет и вызывает его через собственный MCP-сервер, результат используется в ответе. Обеспечить безопасную обработку аргументов, ошибок и операций с побочными эффектами.

## Постановка

1. Приложение как MCP-клиент к собственному MCP-серверу.
2. Обнаружение tools/resource без дублирования схем в Telegram-handlers.
3. По запросу: обычный ответ / уточнение / вызов инструмента.
4. Погода, расписание на дату, подготовка напоминания.
5. Подтверждение перед созданием напоминания.
6. Явные ошибки внешних систем; команды `/tools`, `/why`, `/timezone`.
7. В PostgreSQL: timezone, напоминания, подтверждения, аудит решений.
8. Автотесты + оценка качества маршрутизации.

Доставка напоминаний по времени — **не в этой работе** (переносится в Lab 3).

## MCP-сервер

Транспорт: рекомендуется `stdio` (Streamable HTTP — только если закрыт снаружи и описан в README).  
У каждого инструмента: `inputSchema`, `outputSchema`, результат в `structuredContent`.

### `get_weather`
- Вход: `city` (1–100 символов после trim).
- Выход минимум: нормализованное место + страна, °C, описание/код, ветер + единица, время наблюдения + TZ данных.
- Обработать: город не найден, несколько одноимённых (вернуть варианты, **не** выбирать первый), таймаут, недоступность, битый ответ.

### `get_schedule`
- Вход: дата `YYYY-MM-DD`.
- Элемент: `start`, `end`, `title`, `location`. Пустой список = нет занятий.
- Источник — из конфигурации; путь к файлу от модели/пользователя не принимается.
- В репозитории — обезличенное расписание ≥ 2 недель.

### `add_reminder`
- Вход модели: `text` (1–500), `remind_at` (будущее ISO 8601 с явным TZ).
- Владелец и ключ идемпотентности — **не** из аргументов модели; из доверенного Telegram update.
- Только после подтверждения; запись в PostgreSQL; возврат id, нормализованного времени, TZ, признака «создана ли новая запись».
- Повтор того же подтверждённого действия не создаёт дубликат.
- Без доверенного владельца — отказ.

### Ресурс `schedule://current-week`
- Расписание пн–вс в настроенной TZ, группировка по датам, тот же формат занятия.
- Границы месяца/года в тестах без сдвига системных часов.

## Команды бота (дополнительно к Lab 1)

| Команда | Назначение |
|---|---|
| `/tools` | список tools с MCP (имя, описание, чтение/изменение); при недоступности сервера — сообщение |
| `/timezone <IANA>` | сохранить TZ; показать локальное время; без аргумента — текущая/не задана |
| `/why` | последнее решение агента: время, действие, tool, резюме аргументов, статус, причина (без секретов/промпта/чужих данных) |

`/start` перечисляет и эти команды.

## Агентный цикл
- Нативный tool calling или структурированный вывод по Pydantic-схеме; **не** regex по тексту модели.
- Модель видит только актуальный список разрешённых схем.
- Решения: respond / clarify / call_tool.
- Неизвестный tool отклонять; погода и расписание — через инструменты, не выдумывать.
- **≤ 2 MCP-вызова** на одно сообщение пользователя.
- До вызова: валидация аргументов (даты, TZ, будущее время, длины, лишние поля, владелец, подтверждение).
- Локальное время напоминания только в сохранённой IANA-зоне; без зоны — сначала `/timezone`.
- Неоднозначное/несуществующее локальное время (DST) — уточнение.

### Подтверждение `add_reminder`
- Показать нормализованные текст/дату/время/TZ; inline «Подтвердить» / «Отменить».
- Привязка к одному пользователю и одному действию; TTL ≤ 5 мин; после execute/cancel — недействительно.
- Изменение текста/времени → новое подтверждение.
- Повтор update / двойное подтверждение → одна операция и одно напоминание.

## Обязательные тесты (минимум)
Погода: успех / не найден / таймаут или битый API.  
Расписание: есть занятия / пусто / неверная дата.  
Напоминание: будущее после confirm / прошлое или пустой текст / идемпотентность / повтор update и concurrent confirm / изоляция пользователей.  
Ресурс недели на границе месяца/года.  
Неизвестная IANA / локальное время без зоны.  
Неизвестный tool / лишние аргументы.  
Плюс ≥ 4 негативных сценария (отсутствующий tool / prompt-injection из данных tool / неоднозначная дата или прошлое / MCP или weather down).

Идемпотентность и concurrent confirm — интеграционный тест на реальном PostgreSQL.

## Эксперимент маршрутизации
Набор: `docs/evaluation/lab2-routing.json` (12 кейсов: 3 weather, 3 schedule, 3 reminder, 2 respond, 1 clarify).

```text
routing_accuracy  = correct_actions / 12     ≥ 10/12
argument_accuracy = correct_args_on_tools / 9 ≥ 8/9
```

Таблица запросов; для ошибок — причина; изменить один элемент решения и перепроверить ошибочные кейсы.
