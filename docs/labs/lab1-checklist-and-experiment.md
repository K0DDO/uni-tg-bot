## 3. Сравнение слабой и улучшенной инструкции

Сделай отдельно от 12 запусков (можно temperature=0.3, один `/reset` перед каждым).

### Слабая инструкция (намеренно плохая)
Временно для демо можно описать в отчёте как гипотетическую; для живого сравнения достаточно попросить бота в study так:

Запрос при «слабом» поведении (чтобы увидеть проблему текущего/слабого стиля):

```text
Расскажи про декораторы
```

Типичные проблемы слабого ответа: нет структуры, нет границ темы, длинная лекция, нет примера или пример с кириллическими именами.

### Улучшенный запрос (R.C.T.F. + ограничения)

```text
Role для тебя в этом сообщении: преподаватель Python для 1 курса.
Context: студент знает функции, ещё не знает замыкания глубоко.
Task: объясни декораторы за 5–7 предложений и дай один короткий пример с english-идентификаторами.
Format: без Markdown; сначала определение, потом зачем нужны, потом пример, потом одна типичная ошибка новичков.
```

В отчёте сравни по заранее названным признакам: структура, полнота, понятность, отсутствие выдумок — не только «понравилось больше».

## 4. Тексты и сценарии для проверки ошибок

### A. Обычный успешный сценарий
```text
/start
/study
Что такое list comprehension в Python? Коротко и с одним примером.
```

### B. Перевод
```text
/translate
Переведи на английский: Лабораторная работа завершена успешно.
```

### C. Экзаменатор
```text
/exam
Срезы списков в Python
```
Потом ответь на вопросы бота своими словами.

### D. Некорректный temperature (до API)
```text
/settings 2
```
Ожидание: отказ «Допустимы: 0.0, 0.3, 0.7, 1.0», без вызова модели.

### E. Сброс истории
```text
/study
Запомни кодовое слово: абрикос
/reset
Какое кодовое слово я назвал?
```
Ожидание: бот не знает / не помнит «абрикос».

### F. Изоляция пользователей
С двух Telegram-аккаунтов (или свой + друга): разные истории и разные temperature не пересекаются. После рестарта бота контекст из БД восстанавливается.

### G. Ошибка API / недоступность (демо для защиты)
1. В `.env` временно поставь неверный `OPENROUTER_API_KEY=sk-or-invalid`.
2. Перезапусти бота.
3. Отправь любой учебный вопрос.
4. Ожидание: короткое русское сообщение вроде «сервис модели временно недоступен», без traceback и без ключа.
5. Верни правильный ключ.

Альтернатива без порчи ключа: на время выставь `LLM_TIMEOUT_SECONDS=1` и задай тяжёлый запрос — чаще поймаешь таймаут.

### H. Длинный ответ (>4096)
```text
/study
Напиши очень подробный конспект по ООП в Python на 10 разделов: каждый раздел минимум 8 предложений, с примерами кода. Нужен максимально длинный текст.
```
Ожидание: ответ придёт несколькими сообщениями подряд, текст не обрежется посередине смысла кусками ≤4096.

### I. Пустой/мусорный ответ модели
Сложно воспроизвести стабильно. Для отчёта достаточно указать: в коде есть `LLMEmptyResponseError` и пользовательское «Модель вернула пустой ответ…»; подтверждено автотестом ошибки LLM / веткой в `app/handlers/chat.py` и `app/llm/client.py`.

### J. Антигаллюцинация (регресс)
```text
/reset
/study
что такое сиксевен?
```
Ожидание: отказ/уточнение, а не выдуманный язык программирования.

## 5. Каркас выводов для отчёта (можно почти дословно)

**Temperature:** при 0.0 ответы наиболее стабильны по структуре «три абзаца», длина близка; при 1.0 выше вариативность формулировок и риск нарушить формат. Для режима `/study` оптимален temperature 0.3 (или 0.7 — по твоей таблице): достаточно ясности при умеренном разнообразии.

**Слабая vs улучшенная инструкция:** запрос без Role/Context/Task/Format даёт размытый ответ; R.C.T.F.-формулировка повышает соблюдение структуры и появление примера с english-идентификаторами.

**Ограничение:** модель всё ещё может ошибаться в фактах; промпт снижает, но не устраняет галлюцинации. Нет стриминга токенов в UI — для таблицы токенов смотри кабинет OpenRouter.
