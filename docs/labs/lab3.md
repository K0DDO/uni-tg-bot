## Что известно из методички

Из аннотации и введения (`docs/labs-guide.md`):

1. Обработка запросов **разделяется между специализированными компонентами**.
2. Приложение получает **проактивные сценарии**.
3. Добавляются **средства трассировки**.
4. Работа опирается на результат Lab 1 и Lab 2; перед стартом — сохранить предыдущий этап в Git и тег `lab3` по сдаче.

### Понятия, явно связанные с Lab 3

**Маршрутизация (routing)** — выбор компонента, который обработает запрос.  
**Специализация (specialization)** — ограниченное назначение компонента, свои инструкции и набор инструментов; независимое тестирование и принцип наименьших привилегий.

**Проактивный сценарий (proactive workflow)** — запуск по событию или расписанию, а не по новому сообщению пользователя. Примеры из методички:
- доставка наступившего напоминания;
- утренняя сводка.

Требования к проактивности (из раздела понятий): контроль частоты, повторной доставки, часового пояса, сохранение состояния между перезапусками.
