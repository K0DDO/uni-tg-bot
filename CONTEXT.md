# Контекст приложения: uni-tg-bot / itmo_tg_bot

> **Обязательно читать этот файл** после обнуления контекстного окна (нового чата / сжатия истории), прежде чем продолжать работу над проектом.

## Цель проекта

Сквозной учебный проект курса «Технологии искусственного интеллекта в разработке ПО»:
AI-ассистент студента на базе Telegram-бота (Python 3.12 + PostgreSQL + aiogram).

Три этапа (лабораторные):

1. **Lab 1** — диалог с LLM, режимы, история, настройки генерации.
2. **Lab 2** — AI-агент с собственным MCP-сервером (погода, расписание, напоминания).
3. **Lab 3** — специализация/маршрутизация компонентов, проактивные сценарии, трассировка (полное ТЗ ещё не опубликовано).

Подробные условия заданий: `docs/labs/`.

Исходный шаблон: https://github.com/K0DDO/uni-tg-bot  
Методичка: `docs/labs-guide.md`.

## Правила взаимодействия с ассистентом

1. **Каждый запрос пользователя** записывать в `CHAT_HISTORY.md` (только текст запроса пользователя; ответы ассистента не писать).
2. **Каждую фичу и любое своё действие** фиксировать отдельным git-коммитом.
3. Сообщение коммита: **короткое описание на английском**, с **маленькой буквы**, **без точки на конце**.
4. После каждого коммита **сразу делать `git push`** на remote.
5. После обнуления контекста сначала читать этот файл и `CHAT_HISTORY.md`, затем `docs/labs/`.
6. Секреты (токены, ключи API, пароли БД) не коммитить и не светить в логах/отчётах.
7. Не ломать локальный запуск, healthcheck и корректное завершение приложения из шаблона.
8. Новые обработчики команд подключать **перед** echo-роутером.

## Текущее состояние репозитория

- Стартовый **echo-бот**: long polling, ответ тем же текстом.
- PostgreSQL через asyncpg (проверка `SELECT 1`), учебных таблиц нет.
- Docker Compose для локальной БД и облачного деплоя (Yandex Cloud).
- Тесты обвязки, ruff, скрипты `scripts/start.*` / `scripts/deploy.*`.
- Функциональность лабораторных **ещё не реализована**.

### Автодеплой (VPS)

- Триггер: push в `main` или ручной `workflow_dispatch`.
- На сервере нужен git-клон репозитория с `compose.yaml` в одном из путей: `~/uni-tg-bot`, `~/itmo_tg_bot`, `~/course-bot`, `/opt/uni-tg-bot`, `/opt/itmo_tg_bot`, `/home/student/course-bot`.
- На сервере должны быть Docker + Compose v2 и файл `.env.cloud` (или `.env`) с секретами; workflow их не создаёт.
- Деплой: `git fetch/reset origin/main` → `docker compose --profile cloud up -d --build --wait`.
